# 城市露天电影放映审批与设备巡检平台

围绕**同一场放映**，串联申请方（社区/物业/商圈）、文化审核员、仓库、现场负责人、安保、财务、街道文体岗的全流程协同系统。

- 前端：Vue 3 + Vite + TypeScript + Element Plus + Pinia（端口 5173）
- 后端：NestJS 11 + TypeORM + JWT（端口 3000，`/api` 前缀）
- 数据库：PostgreSQL 15（本项目使用**用户态集群**，端口 5433，无需 root / docker）

## 一、功能与业务闭环

1. **放映申请**：放映日期、场地位置、预计观众、影片版权凭证（上传）、供电条件、银幕尺寸、音响数量、安保人员、雨天预案；黑名单场地、被暂停主办方在提交时直接拦截。
2. **文化审核**：核对影片授权编号 + 公共活动备案号，可驳回（申请方修改后重提）；点位历史噪声/损坏连续超标时强制二次确认风险，影响下一轮审批。
3. **仓库成套备料**：投影机、幕布、音箱（按音响数量）、电缆、备用灯泡、防雨罩六大类缺一不可，已占用设备不能重复备料。
4. **扫码领取**：逐件扫描设备二维码核对成套状态，非本场清单设备当场拒绝（防错拿），全部核对一致才准入放映当天。
5. **当天巡检**：现场负责人上传搭建照片、试播截图，填写噪声分贝（>55dB 自动判定超标）、观众区域隔离、消防通道情况，并填报实际观众后结束放映。
6. **七类异常跨角色协同**：影片文件损坏、设备缺件、居民投诉噪声、临时降雨、观众超员、供电跳闸、商户要求延长活动；每起事件有独立协同消息线程（申请方/审核/仓库/现场/安保/财务均可发言），延时申请须审核员/街道审批并同步场次结束时间，处理完填写结果才能关闭。
7. **归还与赔付**：仓库逐件验收，损坏/遗失登记赔付，自动从主办方押金抵扣、不足转为待补缴；设备状态自动回库。
8. **核销闭环**：异常全部关闭后财务才能核销——补贴发放、版权凭证核销、主办方信用结算、点位噪声/损坏次数累计；信用低于 60 自动暂停申请资格，点位噪声累计 3 次自动拉黑。
9. **信用 / 押金 / 志愿者 / 黑名单**：主办方信用变动明细、设备押金收取与退还、志愿者签到签退、场地黑名单手动/自动管理。
10. **街道时间线**：按“申请→审批→出库→搭建→放映→投诉→核销”时间线追踪全场活动；总览看板展示状态分布、风险点位、低信用主办方、设备占用与未闭环异常。

## 二、本地启动

> 环境要求：Node.js ≥ 20、PostgreSQL 15 服务端程序（`/usr/lib/postgresql/15/bin`，Debian/Ubuntu 安装 `postgresql-15` 即可）。
> 若已有可用的 PostgreSQL，可修改 `backend/.env` 中的连接信息，跳过第 1 步。

```bash
# 0) 如遇 ~/.npm 权限问题，可设置项目内缓存：
export npm_config_cache=$PWD/.npm-cache

# 1) 启动用户态 PostgreSQL（首次自动 initdb + 建库 openair_cinema，端口 5433）
bash scripts/db-start.sh

# 2) 启动后端（终端 A）
cd backend
npm install
npm run seed          # 初始化表结构 + 种子账号/场地/设备/示例场次
npm run start:dev     # http://localhost:3000/api

# 3) 启动前端（终端 B）
cd frontend
npm install
npm run dev           # http://localhost:5173
```

打开 http://localhost:5173 ，用下方测试账号登录（密码统一 **123456**）。

停止数据库：`bash scripts/db-stop.sh`；重置演示数据：在 `backend` 下重新执行 `npm run seed`。

## 四、推荐手动验证路径（浏览器）

1. `street` 登录 → 看总览（风险点位、信用预警、设备概况）与活动时间线。
2. `applicant1` 登录 → 新建放映申请（上传版权凭证；试选黑名单场地会被禁用，提交也会被后端拦截）。
3. `reviewer` 登录 → 打开 `SS-20260927-001` → 文化审核 Tab：首次通过会被“高风险点位”拦截，勾选确认后填写授权号/备案号通过。
4. `warehouse` 登录 → 设备出库 Tab：故意不选音箱会提示成套缺件；按 9 件配齐备料。
5. `leader` 登录 → 输入 `EQ-PJ-002` 扫码（应被拒绝），再依次扫描清单 9 个二维码 → 自动进入放映当天。
6. 当天巡检 Tab 上传两张图片、填 62dB、隔离与消防通道 → 提交（噪声判超标）；填报实际观众后结束放映。
7. 异常协同 Tab：用不同账号（可换浏览器/重新登录）上报噪声投诉、缺件、降雨、延时申请；在消息线程里协同；`reviewer` 审批延时；逐起关闭。
8. `warehouse` 验收入库：将 1 只音箱标记损坏赔 800 → 押金自动抵扣。
9. `finance` 核销：有未关闭异常时会被拦截；全部关闭后发补贴 + 版权核销 → 信用扣到 70、点位噪声累计 3 次自动拉黑。
10. 「主办方信用」「场地黑名单」「财务记录」「活动时间线」查看联动结果。

## 五、自动化验证

```bash
# 前置：数据库已启动（scripts/db-start.sh）、后端已启动（backend: npm run start:dev）
bash scripts/e2e.sh
```

脚本自动重新播种并用 curl 走通 13 个场景、28 项断言。

**本次实际验证结论（2026-09-26 执行）：通过 28 / 失败 0**，覆盖：

- 黑名单场地 / 被暂停主办方申请拦截（另手工验证低信用主办方返回 HTTP 403）；申请方数据隔离；
- 风险点位审核强制确认；授权号/备案号写入；
- 成套备料缺件拦截、占用设备拦截、重复备料拦截；
- 扫码核对成套状态、非本场设备拒绝、9 件齐套后自动流转；
- 志愿者签到/签退；巡检五项与 55dB 超标判定；
- 噪声投诉/缺件/降雨/延时 4 起异常的多角色消息线程、延时审批同步结束时间、异常关闭；
- 结束放映 → 归还验收（损坏赔 800 押金抵扣，余额 5000→4200，其余自动回库）；
- 核销：未关闭异常拦截（独立场次验证）、异常场信用 100→70（-10 噪声超标 / -5 投诉 / -5 缺件 / -10 赔付）、点位噪声累计 3 次自动拉黑；
- 零异常场信用 +2、补贴发放；供电跳闸场关闭异常后可核销（-5）；
- 街道总览统计正确（3 场次/风险点位/1 件损坏设备），时间线 66 条事件；
- `backend` `nest build`、`frontend` `vite build` 均编译通过；Vite 开发服务首页 200、`/api` 代理生效。

## 六、主要接口一览

| 方法 & 路径 | 角色 | 说明 |
| --- | --- | --- |
| `POST /api/auth/login` | 公开 | 登录获取 JWT |
| `POST /api/sessions` | 申请方 | 提交放映申请（黑名单/信用校验） |
| `POST /api/sessions/:id/review?confirmRisk=` | 审核/街道 | 影片授权 + 备案审核 |
| `POST /api/sessions/:id/resubmit` | 申请方 | 驳回后修改重提 |
| `POST /api/sessions/:id/prepare` | 仓库 | 成套备料（六类必备校验） |
| `POST /api/sessions/:id/scan` | 仓库/现场 | 二维码领取核对 |
| `POST /api/sessions/:id/inspection` | 现场 | 当天五项巡检 |
| `POST /api/sessions/:id/finish` | 现场 | 填报实际观众、结束放映 |
| `POST /api/sessions/:id/incidents` | 各参与方 | 上报七类异常 |
| `POST /api/incidents/:id/messages` | 各参与方 | 协同消息线程 |
| `POST /api/incidents/:id/decision` | 审核/街道 | 延时申请审批 |
| `POST /api/incidents/:id/close` | 现场/安保/审核/街道 | 填写处理结果关闭 |
| `POST /api/sessions/:id/return` | 仓库 | 归还验收 + 赔付押金抵扣 |
| `POST /api/sessions/:id/settle` | 财务/街道 | 补贴/版权/信用/点位核销 |
| `GET /api/dashboard/overview` · `/timeline` | 登录用户 | 街道总览与全量时间线 |
| `POST /api/upload` | 登录用户 | 版权凭证/现场照片上传（multipart，字段名 `file`） |
